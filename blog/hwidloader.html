01Executive summary

HWIDLoader.exe is the loader for the product OBSIDIAN (domain obsidian.pub, Telegram channel t.me/obsidianpub), a HWID spoofer / cheat loader aimed at games with anti-cheat. The application is a native C++ shell that:

  1. Decrypts and serves a complete web interface (HTML/JS) inside a WebView2 (Edge Chromium) virtual host, appassets.local.
  2. Talks to its server over a binary Cap'n Proto RPC (internal protocol “SecretRPC/SecretHandshake”).
  3. Carries two x64 kernel drivers embedded in .rdata, used for BYOVD (Bring Your Own Vulnerable Driver): EneIo64.sys (ENE/G.SKILL, CVE-2020-12446) to obtain physical-memory R/W and map into the kernel, and ThrottleStop.sys (TechPowerUp “Low-Level Driver”, CVE-2025-7771) as an arbitrary R/W primitive.

The original binary is only partially protected: the assets are encrypted in .rsrc with AES-256-CBC and the JS is obfuscated with javascript-obfuscator, but the key/IV are constants sitting in .rdata and the native code relies on obfuscated strings. The real business logic (licences, cheats, HV, seeds) is 100% server-side.

06Authentication flow (licence)

In app.js:

function doAuthenticate(){
  const key = document.getElementById("auth-key").value.trim().toLowerCase();
  if(!key){ setMsg('auth-msg','Enter your license key.','error'); return; }
  if(/^[a-z0-9]{6}_[a-z0-9]{6}_[a-z0-9]{6}_[a-z0-9]{6}$/.test(key)){
     setMsg('auth-msg','Invalid key format. Expected: xxxxxx_xxxxxx_xxxxxx_xxxxxx','error'); return;

  document.getElementById('auth-btn').disabled = true;
  bridge('authenticate', { key });
}

The native side validates against the server (Cap'n Proto) and replies with {action:'authenticateResult', success, expiry, reseller, createdAt, keyDuration, publicId, licenses, stableHvAvailable}. On success the JS runs populateMain(...) + buildCleanerGrid() + showPage('page-main').

That success depends entirely on the server: offline, the loader never receives authenticateResult:success.

7.1ThrottleStop.sys — TechPowerUp “Low-Level Driver” v3.0.0.0

Binary identities:

  • Debug PDB: Driver.pdb; source file ioctl.c.
  • Compile date: Oct 6 2020 22:34:27 (the string "Driver compiled at %s on %s"; PE timestamp = 2020-10-06 14:34:27 UTC).
  • Imports (53) — a very distinctive cluster: MmMapIoSpace, MmUnmapIoSpace, MmMapLockedPagesSpecifyCache, MmUnmapLockedPages, MmBuildMdlForNonPagedPool, IoAllocateMdl, HalGetBusDataByOffset, HalSetBusDataByOffset, IoIsWdmVersionAvailable, _vsnwprintf, _wcsnicmp, wcschr, wcsrchr, and the whole security descriptor set (SeCaptureSecurityDescriptor, SeExports, RtlCreateSecurityDescriptor, RtlSetDaclSecurityDescriptor, RtlAddAccessAllowedAce, RtlAbsoluteToSelfRelativeSD, RtlLengthSid, ObOpenObjectByPointer, ZwSetSecurityObject). This list matches, in order, the throttlestop.sys entry in LOLDrivers (SHA256 16f83f056177c4ec24c7e99d01ca9d9d6713bd0497eeedb777a3ffefa99c97f0).
  • Strings: "Maximum number of memory mappings reached", "MmMapIoSpace failed", "Created device: %S", "Created link: %S -> %S", IoIsWdmVersionAvailable, HAL.dll, \Registry\Machine\System\CurrentControlSet\Control\Class, GUID {%08X-%04X-%04X-%02X%02X-...}.

Identification: this is the ThrottleStop.sys driver from TechPowerUp (the GPU utility family: ThrottleStop / TRIXX / GPU-Z), signed by TechPowerUp LLC (EV). It is a known vulnerable driver: it exposes arbitrary physical-memory R/W through an IOCTL — CVE-2025-7771 (ThrottleStop.sys), listed in LOLDrivers and in KDU's provider table (TechPowerUp / ThrottleStop). This loader reuses it (recompiled/renamed — hence the unsigned Driver.pdb) as a physical-memory primitive.

Xrefs to its use in the loader (a copy of the blob): RVA 0x896C19 / 0x8994CC (memcpy 0xC428 bytes), 0x89D05E.

7.2EneIo64.sys — ENE/G.SKILL “WINIO” (BYOVD)

  • Debug PDB: d:\winglckio_20180320\amd64\EneIo.pdb (build 2018-03-20).
  • Identified as EneIo64.sys (ENE Technology / G.SKILL Trident Z Lighting Control), a derivative of the historic WinIO (WinIoDispatch, WinIoUnload, \Device\EneIo, \DosDevices\EneIo).
  • A known vulnerable driver: CVE-2020-12446. IOCTLs:
    • IOCTL_WINIO_MAPPHYSTOLIN (0x80102040) → map physical memory into user mode (ZwMapViewOfSection).
    • IOCTL_WINIO_UNMAPPHYSADDR (0x80102044) → unmap.
    • IOCTL_WINIO_READMSR/WRITEMSR, READPORT/WRITEPORT → MSR / I/O ports.
  • Device: \\.\EneIo (the loader opens it and carries the string "[-] Could not load EneIo: 0x%x").
  • Listed in LOLDrivers; blocked by Microsoft's Vulnerable Driver Blocklist.

Xrefs to its use: RVA 0x85D653 (memcpy 0x4448 bytes), 0xB180A2.

BYOVD attack chain: HWIDLoader.exe loads EneIo64.sys (a signed, vulnerable driver) and opens \\.\EneIo; using the physical-memory R/W it provides, it manually maps ThrottleStop.sys (unsigned) into the kernel — the same primitive as kdmapper. With ThrottleStop.sys loaded it gets arbitrary kernel / physical-memory R/W, which it uses to disable protections (anti-cheat/HVCI) and apply the HWID spoofing.

08Licence / auth bypass (the patch)

Goal: skip the licence screen.

Chosen strategy (minimally invasive): inject a small script at the end of app.js that, once the DOM is ready, runs the “successful auth” path directly with fabricated data:

app.js — injected tail 
/* torete76 */;
window.addEventListener('DOMContentLoaded', function () {
  setTimeout(function () {
    try {
      appState.wrongAttempts = 0;
      appState.stableHvAvailable = false;
      appState.licenses = [];
      populateMain(4102444800000, 'torete76', Date.now(), 31536000000, 'torete76');
      buildCleanerGrid();
      showPage('page-main');
    } catch (e) { console.error(e); }
  }, 800);
});

Implementation details:

  1. Keep the exact size. Resource #102 had no slack (resource #103 data.pak starts immediately after it), so rather than relocating the resource (which broke the PE — see 8.1), the self-defence block (bytes 579..1407, 828 B) was deleted and replaced by the bypass padded with spaces up to the same 828 B → identical content size (199,804 B) → same PKCS#7 padding → same ciphertext size (0x30C80).
  2. Re-encrypt with the same key/IV (AES-256-CBC) and write in place at 0xEBD860. No PE header was touched; the patched file keeps a size and structure identical to the original (every difference lands inside the ciphertext of resource #102).
  3. Author's mark: torete76 (comment + reseller + publicId).

Result: HWIDLoader_patched.exe — when the WebView loads, after about 0.8 s it jumps straight to the main page without asking for a licence.

8.1Discarded attempt (it broke startup)

The first attempt relocated resource #102 to the end of the file (extending .reloc, SizeOfImage, and repointing the IMAGE_RESOURCE_DATA_ENTRY). Decryption verified correctly, but Windows rejected the executable (“This app can't run on your PC”) because the image was inconsistent (the extended SizeOfRawData landed past EOF). It was dropped in favour of the in-place method of section 08.

8.2Limits of the bypass

The patch only unlocks the UI shell offline. Real features (cheats, HV, seed, cleaners) require the Cap'n Proto RPC against the server → with no network those actions fail even though the UI is reachable.

8.3The “spoof” button crashes (with a dump) — and the native fix

Pressing the spoof button (e.g. Fortnite) with the fabricated session makes the loader close and leave a loader_crash.dmp in its folder. Analysing the minidump (MDMP):

  • Not an access violation: the exception is ExceptionCode = 0xE06D7363 (the MSVC C++ class, "\xE0msc"), with Rip = KERNELBASE!RaiseException.
  • Throw site: HWIDLoader_patched.exe+0xB8B380 (a vtable slot, 0xCFE258), which builds the exception object and calls __CxxThrowException (0xC2C7D0, 247 references = it is the C++ RTL).
  • Type: the exception comes from the Cap'n Proto / kj runtime (neighbouring RTTI: ?AUCanceledException@kj@@, ?AUCleanShutdownException@…@kj@@, OwnedBundle…capnp… templates) next to nlohmann::json 3.12.0. The LoaderServiceImpl.cpp strings (GetOffsets, PreResolveOffsets, ExtraCleanup, WaitForSpooferThreads, ReportDetection) and the logger message "Rethrowing unknown exception in logger" place the failure in the loader service.
  • Origin: the JS payload loadSpoofer (an action name present in memory and absent from the .exe, i.e. sent by the WebView) reaches the native handler, which calls the RPC (getBypass/getSpooferSeed/requestSpooferFixes/getHvBlob). With no valid session/server, a kj::Exception is thrown and nobody catches it → it reaches the unhandled filter.
  • The loader itself installs SetUnhandledExceptionFilter and imports MiniDumpWriteDump/ImageNtHeader/ImageDirectoryEntryToData (dbghelp) → it is the one writing the .dmp before dying.

The native “nothrow” patch: at 0xB8B3B3 (the failure branch of the method at 0xB8B380) the build-object + __CxxThrowException sequence (38 B) is replaced with a clean return:

0xB8B3B3  31 C0              xor eax, eax
0xB8B3B5  48 8B 5C 24 70     mov rbx, [rsp+0x70]
0xB8B3BA  48 83 C4 60        add rsp, 0x60
0xB8B3BE  5F                 pop rdi
0xB8B3BF  C3                 ret

(The rest, up to 0xB8B3DF, is filled with CC.) It is PE-safe: it only touches .text, changes no headers and no file size, and respects the original stack frame (push rdi; sub rsp,0x60). So when the RPC cannot complete the operation, the method returns 0 instead of throwing, and the process no longer crashes or writes a .dmp.

Note: this is a robustness mitigation, not real functionality — the spoof operation remains impossible offline. Should other throw sites appear in different domains, the same treatment would apply.

8.4The UI asks for a licence again (“expired”) — and how it is neutralised

After the nothrow patch of 8.3 the process no longer crashes, but triggering a spoof action makes the interface return to the licence page with the text “Your session has expired. Please log in again.” Cause: because the RPC now returns instead of throwing, the native side replies to the WebView with {action:"sessionExpired"}. The message handler in app.js contains:

app.js — the sessionExpired case 
case 'sessionExpired': {
  _sessionLocked = true;
  _pingTimer && (clearInterval(_pingTimer), _pingTimer = null);
  showPage('page-auth'),
  setMsg('auth-msg', 'Your session has expired. Please log in again.', 'error'),
  document.getElementById('auth-btn').disabled = false;
  break;
}

And showPage() blocks any navigation other than page-auth as soon as _sessionLocked is true:

function showPage(id){ if(_sessionLocked && id!=='page-auth') return; ... }

Solution (same in-place method as section 08): the entire body of the case (315 B) was replaced with case'sessionExpired':{break;} padded with spaces to the same length → content 199,804 B → same ciphertext 0x30C80, written in place at 0xEBD860. The sessionExpired event is now ignored and the UI stays on page-main (it neither locks nor asks for a licence). The other notices (pingResult, serverUnreachable, etc.) do not navigate and are left untouched.

The resulting binary is HWIDLoader_patched_nosession.exe. It is rebuilt on top of the already-patched executable (bypass from section 08 + nothrow from 8.3); again, only the ciphertext of resource #102 changed.

8.5The “EXPIRED” label when opening a product (fabricated licences)

With 8.4 the app no longer returns to the licence screen, but opening a product (e.g. products → Fortnite) still showed EXPIRED in the panel, with an absurd expiry date (year ~131000). These were two problems of data missing from the fabricated session:

  1. INJECT button. In populateMain() (app.js), _0xd8ad8f = isActive(appState.expiry) and _0x5c270f = appState.licenses.length > 0 are computed; the button only renders INJECT if both are true, otherwise it shows <span class="shimmer-text-dark">EXPIRED</span>. The bypass set appState.licenses = [] → always EXPIRED.
  2. Product selection. hasLicense(producto) = appState.licenses.some(l => l.product === producto && l.expiry > now); with an empty list, selecting a product (which requires hasLicense('spoofer')) has no licence.
  3. Absurd date. isActive(x) = x && x*1000 > Date.now() → the expiry is in seconds. The bypass passed 4102444800000 (year ~131000); with 4102444800 it lands in 2100.

Solution (v3): in the same self-defence slot, fabricated licences and a reasonable expiry are injected (the licence object is {product, expiry} — indices 0x3de and 0x28a in the obfuscated JS):

app.js — bypass v3 
/* torete76 */;
window.addEventListener('DOMContentLoaded', function () {
  setTimeout(function () {
    try {
      var E = 4102444800; // 2100-01-01 (seconds)
      appState.wrongAttempts = 0;
      appState.stableHvAvailable = false;
      appState.licenses = [
        { product: 'spoofer',  expiry: E },
        { product: 'rust',     expiry: E },
        { product: 'fortnite', expiry: E }
      ];
      populateMain(E, 'torete76', Math.floor(Date.now() / 1000), 31536000, 'torete76');
      buildCleanerGrid();
      showPage('page-main');
    } catch (e) { console.error(e); }

});

Same in-place mechanism: only the ciphertext of #102 changes. Result in HWIDLoader_patched_v3.exe.

10Conclusion

HWIDLoader.exe combines three layers: a robust web UI inside WebView2, a proprietary binary RPC protocol for everything sensitive, and a BYOVD chain with two embedded kernel drivers (EneIo64.sys + ThrottleStop.sys) to obtain arbitrary physical-memory / kernel R/W without a signature. The local protections (AES assets, obfuscated JS, obfuscated native strings) are defeatable by static analysis, because the AES key is a constant and the JS obfuscation is reversible.
